# Tenant storefront pricing modes

## Context
Tenant storefront owners already have a 0–500% markup setting: zero uses the public/user catalog total and a positive value applies markup to the colleague total. Add a second, owner-selected pricing mode with explicit whole-toman prices for normal-service GB/day, national-service GB, and each unlimited plan. Owner-facing pricing messages must show both the owner's computed colleague cost and the customer's price; custom prices cannot be below the corresponding colleague cost. Preserve the percentage mode and its existing orders.

## Verified starting points
- `Services/TenantBotService.cs` owns `CalculateTenantPrice(BotInstance, XuiV3PurchaseSelection)` (lines 13548–13579): it resolves public and colleague totals, uses public at zero markup, applies positive markup to colleague, and enforces total sale >= base. An unlimited plan with `TenantUsesUserPrice` currently returns the public total before applying markup.
- The same file has owner panel `BUILDOWNERPANELTEXT` and `BUILDOWNERPANELKEYBOARD` (lines 1367–1443), `STARTOWNERINPUTASYNC` (2028–2090), and `SAVETENANTMARKUPASYNC` (2293–2310). Metered customer breakdown and effective rate helpers (13610–13727) currently derive from public or colleague+markup.
- `Services/TenantBotService.PurchaseDiscounts.cs:193–203` rejects a quote when its stored gross/base differ from fresh `CalculateTenantPrice`; renewal and wallet paths also re-evaluate current price through that method.

- `Data/xui-v3-service-plans.json:5–225` currently has `national` (GB rate, no daily rate), `normal` (GB/day rates, finite/custom durations), and `unlimited` (fixed prices per plan). `XuiV3PurchaseService.ResolveTenantPurchase` and `CalculateMeteredPriceBreakdown` (`Services/XuiV3PurchaseService.cs:270–335,687–757,816–823`) supply enabled tenant-visible choices, colleague costs, lifetime multiplier and final ceiling rounding; do not change global owned-bot rates.
- Owner callbacks are revision- and store-number-bound by `TenantOwnerCallback.Encode/TryDecode` (`Services/TenantOwnerCallback.cs:15–50`), with sender/selected-store authorization in `TenantBotService.TryHandleOwnerCallbackAsync` (`:542–605`); owner text dispatch rechecks owner/store (`:388–475`). The discount editor's bot-scoped draft pattern is in `Services/TenantBotService.Discounts.cs:13–36,53–110`.
- Pricing must persist on the tenant `BotInstance` (`Domain/BotRuntime.cs:81–122`, `Data/UserDbContext.cs:350–381`), project through `BotRuntimeServices.ToConfig` (`Services/BotRuntimeServices.cs:105–149`), and reset only on full storefront reset (`TenantBotService.cs:1719–1756,1909–1942`). `BotUserState.FromUser/ToUser/ApplyPartial/Clear` (`Domain/BotRuntime.cs:653–815`) persists and clears owner drafts.
- Confirmed behavior choices: manual mode cannot be activated until all currently enabled tenant offerings have valid prices; manual per-plan price takes precedence over `TenantUsesUserPrice`, which remains effective in percentage mode.
## Approach

### 1. Store the two pricing modes without changing existing tenants
- Add `TenantPricingModes.Percent = "percent"` and `TenantPricingModes.Manual = "manual"` in `Domain/BotRuntime.cs`; add `BotInstance.TenantPricingMode` (non-null, default `percent`), nullable `TenantNormalPricePerGbToman`, `TenantNormalPricePerDayToman`, `TenantNationalPricePerGbToman` (`long?`), and nullable `TenantUnlimitedPlanPricesJson` (nested JSON object `{serviceKey:{planKey:wholeTomanPrice}}`). Add the same runtime fields to `BotInstanceConfig`; document units, store scope, null/unconfigured behavior, and manual-mode priority. A nested map avoids collisions if two unlimited services use the same plan key; use exact catalog keys, case-insensitive lookup, and never Telegram display names as identifiers. Keep `TenantPriceMarkupPercent` unchanged for percentage mode and for switching back.
- Treat an unknown persisted `TenantPricingMode` as invalid rather than silently pricing from public/percent. For manual JSON, parse into ordinal case-insensitive service/plan dictionaries, reject duplicate keys differing only by case and prices outside nonnegative `long` range, and never accept raw JSON from callback payloads; the owner editor constructs it from selected catalog keys and numeric text.
- Map `BotInstance.TenantPricingMode` as required `TEXT` length 16 with default `percent`, the three nullable `INTEGER` prices, and nullable `TenantUnlimitedPlanPricesJson` `TEXT` length 8192 in `Data/UserDbContext.cs`. Add manually attributed users.db migration `Migrations/20260929160000_AddTenantStorefrontPricingModes.cs` and matching `Migrations/UserDbContextModelSnapshot.cs` entries, following the adjacent `20260929150000_AddTenantDiscountCodes` convention. Existing rows migrate to `percent` with null manual prices, retaining every historical order and original markup; Down removes only these new columns. No credentials.db or global catalog price migration.
- Project fields in `BotRegistry.ToConfig` (`Services/BotRuntimeServices.cs`) and configured-bot normalization there; in `Program.SyncBotInstancesAsync` copy them only from the configured bot runtime for configured rows, never overwrite database-owned tenant prices with default config values. New `TenantStoreStore.CreateAsync` rows inherit percent/null defaults. `ResetTenantStorefrontSettings(clearAllStorefrontSettings:true)` clears manual fields and percentage to zero; invalid-token cleanup (`false`) preserves all prices. Verify these persistence changes against current raw-SQL tenant fixtures that omit the new columns.
- Add documented `Services/TenantStorefrontPricing.cs` (no existing tenant manual-price validator) before wiring the editor: `ParseUnlimitedPlanPrices(string json)` returns an ordinal case-insensitive nested price map or rejects malformed/duplicate-key JSON; `TryResolveManualPrice(BotInstance tenant, XuiV3ResolvedPurchase colleague, IReadOnlyDictionary<string, Dictionary<string,long>> unlimitedPrices, out long perGbToman, out long perDayToman, out long fixedPriceToman)` checks the selected service/plan, required rate presence and per-unit/per-plan colleague floors without a database read; `ValidateManualCompleteness(BotInstance tenant, XuiV3ServicePlanCatalog catalog, IReadOnlyDictionary<string, Dictionary<string,long>> unlimitedPrices)` lists precise missing/under-cost active items. The owner editor and later `CalculateTenantPrice` use this single helper. It must not allocate/parse the unlimited map for metered checkout; list renderers parse it once and pass the same map through their price calculations.

### 2. Give each authenticated owner an explicit pricing editor
- Add a `💰 قیمت‌گذاری` button to `BUILDOWNERPANELKEYBOARD`; show the active mode in `BUILDOWNERPANELTEXT` without suggesting zero percent affects manual mode. Implement `Services/TenantBotService.Pricing.cs` (no current multi-rate owner editor) as a partial with an owner-only submenu and `OwnerPricingDraft` storing `TenantBotId`, original `UpdatedAtUtc`/`CreatedAtUtc` revision ticks, eight-hex-character nonce, three nullable rates, parsed nested unlimited prices, and the ordered `(serviceKey,planKey)` identities displayed in the editor. Keep draft only in the selected owned-bot/user conversation: add `OwnerPricingDraftJson` to `Domain/User.cs`, `BotUserState` and its `FromUser`, `ToUser`, `ApplyPartial`, `Clear` in `Domain/BotRuntime.cs`, map it on `BotUserStates` with max length 16384 in `Data/UserDbContext.cs` and the same migration/snapshot. Switching stores and `بازگشت به پنل` cancel this draft; serializing it never changes live prices.
- The draft also stores `EditedRateKeys` for fields changed during this edit session (three fixed field codes or nested service/plan key); `p:save:p` validates those keys against the current catalog without incorrectly rejecting old inactive values that became stale after a later global cost increase. If the owner selects a now-removed plan, do not silently reassign its price to another index; keep its prior saved value inactive and ask to reopen the editor.
- Route `p:*` owner callbacks after the existing `TenantOwnerCallback.TryDecode` colleague/sender/store-number/revision/`OwnerStoreId` checks and before generic `set:` in `TryHandleOwnerCallbackAsync`. Use short actions `p:open`, `p:r:ng:<nonce>`, `p:r:nd:<nonce>`, `p:r:ig:<nonce>`, `p:u:<base36Index>:<nonce>`, `p:page:<base36Page>:<nonce>`, `p:save:p:<nonce>`, `p:save:m:<nonce>` and `p:cancel`; wrap through `TenantOwnerCallback.Encode`, never put free-form plan keys in 64-byte callbacks. Map the index only through the stored draft's ordered service/plan key list and reject missing/mismatched nonce, changed selected store, changed store revision, or removed/hidden plan; refresh the draft/list instead of editing an unrelated plan. Page unlimited plans eight at a time; always render a back/owner-panel action. `p:r`/`p:u` save the chosen key into the bot-scoped draft and set `LastStep="pricing-rate"`; in `TryHandleOwnerMessageAsync` route that step before legacy `STEPMARKUP` to `HandleOwnerPricingTextAsync`.
- The text prompt and editor list each applicable field/tenant-visible enabled unlimited plan with the current colleague rate or fixed plan cost **and** the customer rate/price in whole toman, or `ثبت نشده`; show service/plan names, units (GB/day/plan), active mode and current percent. For a percentage-mode owner summary, show the public unit rate when percent=0, the effective colleague-rate-plus-percent when positive, and for `TenantUsesUserPrice` the public plan price; use actual `CalculateTenantPrice` for any sample whole-order total so ceiling and cost floor are not misstated. These comparisons appear only in authenticated owner messages; tenant customer menus/previews must never expose colleague rates or profit. Parse owner input as one invariant-culture, nonnegative whole-toman `long` (digits only, no separator/negative/overflow; state remains on invalid input); require GB and fixed-plan customer prices >0, allow a zero normal daily price only if its current colleague daily rate is zero, and reject every input below its matching current colleague GB/day/fixed-plan price. Echo both colleague amount and accepted customer amount before returning to the draft editor; cancellation discards uncommitted edits.
- `p:save:p` selects `percent` and persists complete or partial manual-rate drafts for later use; validate every rate newly edited in this draft against the current colleague rate, but old inactive rates made stale by a later catalog increase may remain stored and clearly flagged. The existing `set:markup`/`SAVETENANTMARKUPASYNC` still accepts 0–500 and explicitly selects `percent` on success. `p:save:m` activates `manual` only if normal GB/day and national GB are set whenever those services are enabled and every enabled tenant-visible unlimited plan has a positive price, each at least its **current** colleague unit/plan price; if incomplete, leave the existing mode unchanged. Disabled/hidden plans are not mandatory but their saved prices are retained.
- Update `STARTOWNERINPUTASYNC`'s `STEPMARKUP` prompt to say that saving 0–500 switches to percentage mode (zero means public/user catalog; positive means colleague cost plus percentage); keep its existing input parser and successful save response, then redraw the mode-aware owner panel.
- Both saves re-read exact tenant id + authenticated owner and compare draft revision in one users.db writer transaction, re-load the current catalog, reject changed-rate under-cost values (and all active under-cost/missing values for manual), stale revision, or oversize JSON with precise Persian errors and no partial store update, set `UpdatedAtUtc`, then reload/upsert `_botRegistry` and clear the draft. Reopening the editor loads saved settings; an unsuccessful save leaves the draft for correction. Do not reuse discount callbacks (`d:*`) or customer tenant updates as owner authorization.

### 3. Price tenant sales from the selected mode at one authoritative seam
- Extend `CalculateTenantPrice(BotInstance, XuiV3PurchaseSelection)` in `Services/TenantBotService.cs`, keeping its two `ResolveTenantPurchase` calls for current catalog/audience authorization and exact colleague `BaseCostToman`. In `percent` mode preserve **byte-for-byte financial behavior**: zero uses public total, positive 0–500 computes `Ceiling(colleagueTotal * (1 + percent/100))` and floors at colleague total; unlimited `TenantUsesUserPrice` still wins over the percentage. Never change `XuiV3PurchaseService` global/owned price fields.
- Change the private calculator to `CalculateTenantPrice(BotInstance tenant, XuiV3PurchaseSelection selection, IReadOnlyDictionary<string, Dictionary<string,long>> unlimitedPrices = null)`; existing two-argument callers keep working. In a manual unlimited checkout, parse the saved plan JSON only when `unlimitedPrices` is null. `BUILDTENANTTARIFFSTEXT`, `SHOWSERVICEOPTIONSASYNC` and `BuildTenantRenewUnlimitedKeyboard` decode once and pass the map to each listed plan's calculation; update their callsites and IntelliSense `<param>` docs. Percentage-mode paths do not parse manual JSON.
- For `manual`, use the selected normal/national GB and normal day rates; finite total is `trafficGb * salePerGb + durationDays * salePerDay`, national day uses the unchanged colleague daily rate if a future catalog defines it, and lifetime (days=0) is `trafficGb * salePerGb * LifetimePriceMultiplier` with no day charge. Convert validated multiplier to `decimal`, check arithmetic/`long` overflow and round the whole-order total upward once exactly like `XuiV3PurchaseService.CalculateMeteredPriceBreakdown`; require the result >= the colleague resolved total and >0, otherwise reject rather than silently clamp to base or fall back to percentage/public. For an unlimited service, read its selected service/plan keyed fixed toman price and require it >= the selected colleague fixed price and >0 **even when** `TenantUsesUserPrice=true`; customer profit is `sale-base`. Use a pure documented manual-rate lookup/pricing helper shared by owner completeness checks and checkout; it has no wallet/gateway effects. Parse the nested JSON only for unlimited lookups and once per menu/list render, not once per plan; corrupt JSON, duplicate/colliding keys, missing prices, disabled plans, or current colleague cost increases fail that affected selection closed. A later catalog addition or base-cost increase does not switch the store out of manual mode: newly missing/under-cost offerings are unavailable until the owner repairs prices, while other valid offerings remain available and existing admitted/paid order snapshots are untouched.
- An owner input/rate becoming invalid after a global catalog update must not cause the entire pricing page or bot update to throw: evaluate availability before building price rows, omit only the invalid selection, show a customer-safe “قیمت این گزینه در حال تنظیم است” notice on a stale callback, and show the precise missing or below-colleague entry in the owner editor. Do not catch generic catalog/EF/provider errors and reinterpret them as an unpriced item.
- Update the tenant customer effective-rate helper and metered breakdown (`CalculateTenantEffectiveMeteredRateToman`, `BuildTenantMeteredPriceBreakdownText`) to use the same manual unit rates and unchanged lifetime multiplier while keeping percentage-mode wording/rounding. Update `BUILDTENANTTARIFFSTEXT` so its GB/day lines, sample total, and per-plan unlimited sale all come from the active mode; never show colleague rates on that customer surface. Filter only unpriced/under-cost manual choices in `BUILDTENANTSERVICEKEYBOARD(BotInstance tenant)` (change its sole call in `SendServiceSelectionAsync`), `SHOWSERVICEOPTIONSASYNC`, `SHOWDURATIONOPTIONSASYNC`, `BuildTenantRenewUnlimitedKeyboard` and renewal duration/selection views; retain a back/cancel button and show an explicit customer-safe unavailable-price notice when no valid choice remains. For typed/stale purchase/renewal replies, reject the invalid selection without creating an order or invoice, keep/restart the appropriate selection step and offer current valid options. Include the existing `BuildTenantRenewDurationKeyboard` declaration and its five calls in `HANDLETENANTRENEWSTEPASYNC` when adding tenant/traffic-aware filtering. Do not suppress non-pricing catalog errors silently.
- All purchase payment buttons, customer-wallet admission, renewal summaries/order creation, discount quote preview/admission, and unpaid renewal method activation already call `CalculateTenantPrice` or compare its gross/base (`TenantBotService.cs:5435–5639,6977–7089,7206–8000,8617–8722`, `TenantBotService.CustomerWallet.cs:200–283`, `TenantBotService.PurchaseDiscounts.cs:190–206`, `TenantBotService.RenewalAdmission.cs:22–60`). Keep those single-source callsites; a price-mode/rate change invalidates a stale unpaid preview/quote rather than charging an old amount. Once admitted/paid, provider rows, wallet receipt, discount reduction, owner accounting and ledger keep the persisted `SalePriceToman`, `BaseCostToman`, `ProfitToman` and original quote snapshots; never reprice fulfillment or mutate historical orders.

## Assumptions & contingencies
- The owner-only panel is the recipient of the colleague-vs-customer comparison; exposing colleague costs to tenant customers would reveal private wholesale pricing. Existing customer previews/tariffs show only customer sale values.
- If a new **unknown metered service key** appears in the global catalog, manual-mode activation reports it as unsupported and stays percent; if it is introduced after manual activation, hide that service from manual storefront checkout and show a configuration notice to its owner. Do not silently use global public or colleague prices for an unconfigured service.
